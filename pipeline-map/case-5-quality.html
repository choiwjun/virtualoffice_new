CASE 05 · 검증 → 복구 → 자가개선

품질 게이트와 자가개선 루프

빌드된 코드를 다층으로 검증하고, 실패하면 자동 복구하고, 더 나아가 스스로 개선하는 단계입니다. 검증·복구는 spec이 없어도 코드만으로 바로 돌릴 수 있어, 기존 프로젝트 품질 진단의 진입점이기도 합니다.

① 다층 검증 (Phase 완료마다)
verification-before-completion
"완료/통과" 주장 전 필수. 테스트·린트·빌드 실행하고 증거 확인
/code-review
Stage 1 Spec Compliance → Stage 2 Code Quality
/evaluation
커버리지 ≥70% · 복잡도 ≤10 · 린트 0 · 보안 critical 0
/trinity
五柱(眞善美孝永) 점수. 90+ 자동승인 / 70~89 리뷰 / <70 차단
/audit
OWASP Top 10 · SPDX 라이선스 · GDPR 3모듈 감사
/sync
명세–코드 드리프트 감지 + 자동 수정 제안
/vercel-review
React/Next 성능·접근성·디자인 패턴
/security-review
backend/auth/payment 변경 시 조건부
/chrome-browser
실제 브라우저 클릭 테스트
② 실패 복구 루프 검증 실패 시 자동
검증 실패
테스트/린트/빌드/타입 중 하나라도 실패
▼
/powerqa · 자동 QA 사이클링
테스트 → 검증 → 수정을 목표 달성까지 반복. 최대 5사이클, 동일 실패 3회 시 조기 종료.
최대 5사이클동일 3회 → 중단
동일 에러 3회 이상 = 아키텍처 문제▼
/systematic-debugging · 4단계 근본원인
단순 재시도로 안 풀리는 문제. 가설을 세우고 검증.
① 근본원인 조사② 패턴 분석③ 가설 검증④ 구현+회귀
③ 자가개선 — autoresearch RSI (선택)

Karpathy autoresearch 패턴의 자율 개선 엔진. 3파일 구조 + Frozen Metric + 2계층 RSI(Inner: 코드 개선, Outer: 전략 개선). 코드를 수정 → 테스트 → keep/revert하는 자율 실험 루프를 돌립니다. 8개 서브커맨드로 목적이 갈립니다.

:fix
우선순위 자동 수정 — Build > Type > Test > Lint
:debug
과학적 버그 헌팅 — 가설→실험→증명/반증
:security
OWASP 자율 점검
:ship
출시 준비 자동화
:learn
학습·패턴 추출
:plan
실험 계획 수립
:predict
결과 예측
:scenario
시나리오 탐색
/autoresearch-frontend
프론트 전용. agent-browser(Chrome MCP)로 DOM + 스크린샷 + 콘솔 에러를 Frozen Metric으로 구성 → 코드 수정 → keep/revert
/autoresearch-skills
스킬 자체 개선. 대상 SKILL.md를 수정 → 테스트 케이스 실행 → 메트릭 측정 → keep/revert
보조 · 탐색/사고 도구
/spike
불확실 영역 탐색 전용. 품질 게이트 완화 + 빠른 프로토타이핑 → 결과 리포트
/reflection
에이전트가 자기 출력을 비판적으로 검토하고 반복 개선하는 자기 성찰
/reasoning
Chain/Tree of Thought, ReAct 등 복잡 문제 추론 기법
독립 진입. 이 케이스의 검증·복구·자가개선은 spec이 없어도 코드만으로 바로 실행됩니다. 그래서 "이미 있는 코드의 품질만 진단하고 싶다"면 /reverse 없이 /code-review · /audit · /trinity · /autoresearch:fix를 곧장 돌려도 됩니다.
