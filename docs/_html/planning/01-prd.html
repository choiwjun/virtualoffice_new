1. 표면 요청 → 재정의된 문제 정의

사용자 초기 요청

"3D 가상오피스로 원격 협업을 하면서 회의·업무를 기록하고, 그걸 분기 인사평가에 반영하는 시스템을 만들고 싶어요."

재정의된 한 줄 정의

기존 DailyLog ERP 위에 얹는 3D 프레즌스 + 협업 계층

즉, 우리는:

  • HR/근태/리포트/역량평가 시스템을 재구축하지 않는다
  • 기존 사내 ERP(Space-Daily)를 Source of Truth로 유지한다 (조직·직원·근태·휴가·일일리포트)
  • 3D 가상오피스(아바타·좌석·회의실) + 실시간 프레즌스 + LiveKit 화상회의 + 회의록/협업 기록을 위에 추가한다
  • 그 협업 산출물(회의록·액션아이템·업무결과)을 배치(daily_reports 18:00) 및 관리자 확정 KPI push로 ERP에 전달해서, ERP가 분기별 인사평가 자료로 활용하게 한다 (회의 시간 등 시간 신호는 반감시·이중반영 방지로 KPI 미반영, D14)

2. 제품 정의 & 핵심 원칙

핵심 통찰: "예쁜 3D"가 아니라 "운영 허브"

오피스 경험은 미학이 아니라 업무·회의·KPI가 자연스럽게 쌓이는 구조가 핵심이다.

조직도(ERP) 
  ↓ [읽기 동기화]
우리 org_group (상위 그룹: 본부/부서) + 팀(ERP teams)
  ↓ [직원배정]
좌석 배치 (seat 배정, office_layout JSON 구동)
  ↓ [3D 시각화]
Godot 4 네이티브 3D 클라이언트 (아바타 · 좌석 · 회의실 · 상태)
  ↓ [아바타 출근/상태 변화]
실시간 Presence (Godot 헤드리스 서버 권위)
  ↓ [회의/협업]
회의 시작 → LiveKit 화상 → 회의록 + 액션아이템 생성
  ↓ [업무 기록]
work_log (결과물·완료도) + daily_status
  ↓ [KPI 산출]
협업 산출물 기반 KPI_result (AI 초안 → 관리자 검토 → 조정)
  ↓ [EOD Push]
ERP daily_reports + (신규) kpi_results 테이블로 전송
  ↓ [기말 평가]
ERP가 분기별 인사평가 자료 수집

장점(우리만 할 수 있는 것)

  1. ERP 완전 통합: 직원·조직·근태·휴가는 항상 fresh (read-only DB 직접 접근)
  2. 공간 기반 협업 추적: 근접·회의실 점유·화상 참여를 자동으로 기록
  3. 결과물 중심 평가: 접속시간이 아니라 회의록·액션·완료도로 평가 (반감시 제거)
  4. 운영 가시성: 관리자가 3D맵에서 실시간으로 팀 상태·회의 현황 파악
  5. 사무실 구조 코드화: office_layout JSON으로 구동하므로 좌석·구역·회의실을 앱 빌드 없이 배포/롤백 가능

4. 사용자 페르소나 & JTBD (Job To Be Done)

페르소나 1: 일반 직원 (Individual Contributor)

특성: 팀 소속, 일일 업무 진행, 회의 참여, 결과물 산출 JTBD:

  • When 오전에 출근할 때
  • I want 아바타로 사무실에 입장해서 팀과 나란히 앉아 협업하고
  • So I can 회의·업무를 자연스럽게 진행하고 진행률·결과를 기록해서, 분기 평가 때 내 성과가 공정하게 인정받을 수 있다

필요 기능: 아바타 조작, 좌석 배정, 근처 동료 시각화, 회의 참여, work_log 작성

페르소나 2: 팀리더 (Team Lead)

특성: 팀 5-20명 관리, 일일 상태 파악, 회의 주관, 성과 추적 JTBD:

  • When 아침 스탠드업이나 주간 리뷰를 할 때
  • I want 3D맵에서 우리 팀 구성원들의 출석·업무 상태·진행 중인 회의를 한눈에 보고
  • So I can 누가 온라인인지, 회의실 예약이 이루어졌는지 파악해서 팀을 효율적으로 리드하고, 문제 상황을 빠르게 감지할 수 있다

필요 기능: 팀 시각화, presence 실시간, 회의실 상태, 팀별 KPI 대시보드

페르소나 3: 관리자 (Manager/HR)

특성: 조직 전체 관리, 인사평가, KPI 검토, 정책 수립 JTBD:

  • I want 직원·팀별로 (1) 협업 참여도(회의·회의록), (2) 업무 완료도(work_log), (3) 액션아이템 이행률을 수집하고, 이를 기반으로 AI가 작성한 평가 초안을 검토해서
  • So I can 접속시간이 아니라 실제 협업 성과와 결과물을 기준으로 공정한 평가를 내릴 수 있다

필요 기능: 조직 전체 KPI 대시보드, 개인별 협업 기록 조회, AI 평가 초안 검토·조정, ERP 연동 (결과 저장)

6. KPI & 평가 원칙

핵심: 결과물 중심 평가 (과정 반감시 제거)

반영되지 않는 신호 (반감시 방지):

  • 접속 시간 (몇 시간 했는가)
  • 채팅/메시지 빈도 (얼마나 말했는가)
  • 근접 상호작용 빈도 (몇 번 만났는가)
  • 화상요청 수신/거절 (얼마나 응했는가)

반영되는 협업 신호 (결과물 중심):

  1. 업무 결과물 (work_log)
    • 완료도: started/completed
    • 품질: result_url, issues 기록
    • 충실도: goal·category·next_action 작성 정도
  2. 회의 기여도 (meetingminute + actionitem)
    • 회의 참여 횟수 × 회의록 충실도
    • 자신이 담당한 액션아이템 이행률
    • 회의에서 나온 결정사항 영향도
  3. 업무 기록 충실도 (daily_reports)
    • todaywork·tomorrowplan 작성 완성도
    • blockers 해결을 위한 주도성
  4. 보조: 근태·출퇴근 (기초 근무조건) — KPI 점수에는 직접 반영하지 않음(ERP가 attendance 별도 반영, 이중 반영 금지, D14)
    • 출석률, 휴가 사용 패턴은 ERP 소관 (참고 지표)
    • external(외근/출장)은 수동 전환. GPS 수집 기능 삭제(데스크톱에 GPS 없음, D13/D20)

AI 평가 프로세스

  1. 정량 점수 = 결정론적 코드로 계산 (D14)
    • 완료 work_log 건수·충실도, 액션아이템 완료·기한준수 이행률, 회의록 작성 기여 등을 코드가 산출
    • 시간 비례 점수·회의 참석 기본점·생성 가점·근태 보정은 제거(반감시·이중반영 방지)
  2. AI 초안은 서술만 (Claude — 확정 기본)
    • AI는 강점/개선/근거를 서술하며 정량 점수를 산출하지 않음
    • 외부 AI 전송 시 실명→사번 가명화(D20)
  3. 관리자 검토 & 조정
    • AI 서술은 근거 자료, 최종 판단은 관리자. 정성적 맥락(팀 상황, 조직 변화, 개인 발전) 반영
  4. 직원 이의신청 (상태머신, D15)
    • 평가 공개 → 이의접수(7일) → 재검토 → 확정 → ERP push(final_score)
    • 기록 기반 재검토 가능

7. 성공 기준 & 수용 조건

기술적 성공 기준

  • 3D 클라이언트가 Godot 4 Forward+ 렌더러로 구현되고, 설정된 품질 기준(로비·회의실·아바타·HUD) 샘플 완성
  • ERP 직원·조직·근태 읽기 동기화 완전 자동화 (매시간 증분 + 매일 00:00 KST 전체 대사, D18)
  • office_layout JSON 기반 좌석·회의실 배치가 앱 빌드 없이 배포/롤백 가능
  • 실시간 서버(Godot 헤드리스)에서 도그푸딩 검증 20명(설계 100명)의 동시 접속·아바타 이동·프레즌스 동기화 검증 (D22)
  • LiveKit 화상회의 통합 및 회의록 STT 자동 초안 생성(Egress→STT→화자분리→검토·확정) 테스트 완료 (D5)
  • 관리자 확정 KPI(final_score)가 ERP로 push되고(관리자 확정 이벤트 + 분기 마감), ERP 분기평가에 반영되는 엔드-투-엔드 검증 (D15/D17)

사용성 성공 기준

  • 사내 직원 20명 이상이 1주일 이상 도그푸딩하고 일일 업무를 기록
  • 팀리더가 3D맵만으로 팀 상태를 이해할 수 있다는 피드백 — 정량 지표: 설문 5점 척도 평균 ≥4 (2026-07-02)
  • 관리자가 KPI 대시보드에서 평가 자료를 자신감 있게 수집 가능 — 정량 지표: KPI 수집 파이프라인 오류율 <1% (2026-07-02)

품질 수용 기준 (측정 방법 병기, D22)

  • Godot 클라이언트: 기준 하드웨어 GTX 1650급에서 60fps(내장그래픽 Iris Xe급 최소 30fps), 로딩 < 5초 — 골든 샘플 씬 기준
  • 아바타 동기화: E2E(입력→원격 표시) p95 < 500ms, 서버 tick 20Hz — 측정 구간 명시
  • 화상회의 음성 지연: 사내 LAN < 200ms / 외부(인터넷 UDP 직결) < 300ms 목표, TURN-TLS 폴백 시 측정 병기 (2026-07-02)
  • 회의록 STT 자동 초안 정확도: 주요 발화자·액션아이템 누락률 < 5% — 측정 방법: 테스트 회의 10회의 수동 전사와 대조 (2026-07-02 확정)
  • 브로드캐스트 팬아웃은 O(N²)로 명시, 설계 100명 초과 시 AOI 필터링 + 바이너리 직렬화 도입 검토

운영 수용 기준

  • ERP와의 데이터 동기화 실패 시 자동 알림 및 재시도 로직 (관리자 콘솔 + 알림 채널, D18)
  • 사용자 행동 데이터 (아바타·회의·협업) 감사 로그(audit_log) 남김, 5년 보존 (D20)
  • GPS 수집 기능 없음(데스크톱 무관, D13/D20). external(외근/출장)은 수동 전환. presence 좌표(x,y)는 KPI 미사용·30일 후 삭제
  • 분기 인사평가 프로세스가 ERP와의 연동으로 자동화되고, 수동 개입 줄어듦 — 정량 지표: 주당 수동 개입 건수 기준선 대비 50% 감소 (2026-07-02)
  • 보안 수용 기준 (VPN 없음 → 인터넷 공개 확정, 2026-07-02):
    • 전 구간 TLS: WSS/HTTPS/TURN-TLS
    • 로그인 rate-limit: IP당 10 req/min + 실패 5회 시 지수 백오프 잠금
    • 최소 포트 노출: 443/80만 개방 (onprem-docker §3.2)
    • 도그푸딩 전 보안 체크리스트(onprem-docker §3.3) 통과

Assumptions

  1. 첫 배포는 사내 단일 조직(company_id 고정)이므로, 멀티테넌트 설계는 불필요.
  2. ERP (Space-Daily) DB는 read-only 직접 접근 가능하고, 쓰기는 API 또는 신설 테이블.
  3. 사내 네트워크에서 Godot 데스크톱 설치 → 웹 WASM export는 품질 한계로 배제.
  4. 3D 사무실 구조는 office_layout JSON으로 동적 로드되므로, 매번 클라이언트 빌드할 필요 없음.
  5. 정량 KPI 점수는 결정론적 코드가 산출하고, AI는 서술(강점/개선/근거)만 생성하며, 관리자가 항상 최종 검토(D14).
  6. 직원의 도메인 이메일과 ERP users.id 매핑은 동기화 시 자동 수립.

Validation criteria

  • 페르소나 3종의 JTBD가 모두 구현된 기능으로 충족되는가?
  • KPI 반영 신호들(worklog, meetingminute, action_item)이 모두 수집 가능한가?
  • 관리자 확정 KPI(finalscore) → ERP kpiresults → 분기평가 전체 루프가 폐쇄되는가? (D15/D17)
  • Godot 클라이언트 품질(Forward+, 60fps, 동기화 레이턴시)이 기준을 만족하는가?

Risks

  1. ERP 브랜치 전환 지연: ERP kpiresults 테이블 추가가 지연되면, 우리의 KPI push 쓰기가 블로킹됨 → 완화: 초기 kpiresults를 우리 DB에만 쌓고(feature flag OFF), ERP 준비 후 backfill (D17)
  2. 3D 성능 (설계 100명): Godot 네트워크 동기화 성능 미검증 → 완화: Phase 0 스파이크 S3(헤드리스 부하) + Phase 4 부하 테스트, tick 20Hz, 100명 초과 시 AOI 필터링 (D22)
  3. AI 평가 정확도: 서술 초안 품질이 예상 수준 미만 → 완화: 정량은 결정론적 코드로 고정(D14), AI 서술은 사용자 피드백으로 프롬프트 반복 개선
  4. 사용자 피드백 곡선: 사내 도그푸딩 중 UX 이슈 발견 시 개발 일정 슬립 → 완화: Phase 4부터 주 1회 이상 피드백 수집 체계
  5. Godot ↔ LiveKit 통합 (신규, D20/F): 공식 SDK 부재, WebRTC GDExtension 자체 개발 필요 → 완화: Phase 0 스파이크 S1 PoC, 실패 시 회의 화면만 임베디드 브라우저/외부 창 폴백
  6. STT 정확도 / 한국어 화자분리 (신규, D5/F): 회의록 자동 초안 품질·화자분리 정확도 미달 위험 → 완화: Phase 0 스파이크 S2 PoC, 누락률 <5% 미달 시 수동 회의록 + AI 요약으로 격하(기준 하향 재협의)
  7. 개인정보 / 노동법 컴플라이언스 (신규, D20): 평가 목적 행동 데이터 수집 동의, 회의 녹음·STT 동의, 외부 LLM 전송 → 완화: D20 컴플라이언스 원칙(고지·동의 절차, 사번 가명화, 보존기한, 최소수집 VIEW) 도입 전 이행
