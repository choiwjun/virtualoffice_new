## 1. 납품 폴더 구조 (계약)

```
frontend/public/office2d/
├─ plates/
│   └─ horizon.png            ← 1층 클린플레이트 (인물·이펙트 없는 빈 사무실)
└─ characters/
    └─ {CHARACTER_ID}/        ← 캐릭터별 폴더 (대문자 ID)
        ├─ idle_00.png … idle_05.png   (6프레임)
        └─ walk_00.png … walk_07.png   (8프레임)
```

납품 후 `frontend/lib/office2d.ts`의 `ASSETS_READY = true` 전환 → 플레이스홀더 자동 해제.

| 항목 | 요구값 | 근거 |
|---|---|---|
| 화면비 | **1672:941 (≈16:9)** 고정 — 해상도는 2배(3344×1882)까지 허용 | 좌표 계약(SCENE 20×11.256m)이 이 비율에 캘리브레이션됨. 비율이 바뀌면 realtime 폴리곤 재캘리브레이션 필요(§5) |
| 시점 | 고정 아이소(부감) 단일 시점 | D27~D29 방향 유지 — 카메라 이동 없음 |
| 내용물 | **빈 사무실** — 인물·그림자 인물·모니터 화면 콘텐츠 금지 | 아바타는 런타임 스프라이트로 합성. 구워진 인물이 있으면 이중 표시 |
| 조명·톤 | 균일 톤 1장 — ✅ 시간대 변형은 런타임 테마로 이행(2026-07-16, office2d.ts SCENE_THEMES: 스테이지 필터+앰비언트 오버레이 — 에셋 재굽기 없음, 아바타 동시 톤 변환으로 정합 유지) | 프레임 스프라이트와 톤 정합 필수 — 같은 라이팅 기준으로 제작 |

| 포맷 | PNG(불투명) 또는 WebP, 2MB 이하 권장 | 뷰포트 로딩 < 3초 (01-prd v4.1 §7) |

## 3. 캐릭터 프레임 요구 스펙

| 항목 | 요구값 | 근거 |
|---|---|---|
| 상태·프레임 수 | **idle 6프레임 / walk 8프레임** (엔진 계약 `AVATAR_ANIM`) | 프레임 수 변경 시 office2d.ts 상수만 수정하면 되나, 납품 일관성 위해 고정 권장 |
| 방향 | **우향(→) 기준 1방향** — 좌향은 엔진이 scaleX(-1) 플립 | 8방향 불필요 (엔진이 좌우만 구분) |
| 캔버스 | 프레임 간 발 기준점(bottom-center) 정렬, 투명 배경 PNG | transformOrigin '50% 100%' — 발 고정 애니 |
| 크기 | 세로 380~560px 원본 (엔진이 깊이 기반 축소 표시: 화면높이의 13~17.5%) | avatarHeightFrac 캘리브레이션 |
| 인원 | 8종 (엔진 계약 `CHARACTER_IDS` — ID·이름 변경 가능, 개수 변경 시 상수 동기) | userId 해시 배정 + 아바타 설정 프리셋 |
| 톤 | 플레이트와 동일 라이팅·채도 기준 | D29 실패 교훈 — 배경·인물 톤 불일치가 품질 저하 주범 |
| 추가 상태(후속) | sit / typing (착석 연출) — ✅ sit(2026-07-15)·typing(2026-07-16) 납품 완료. 직군 소품(안경·헤드폰·사원증) ✅ v2.3(2026-07-17) | 06 §3.11 |

## 4. 품질 게이트 (수용 기준 — 01-prd v4.1 §7 연동)

- [ ] 플레이트 단독 육안 QA: 인물·아티팩트 없음, 방 경계 식별 가능
- [ ] 아바타 8종 × idle/walk 프레임 재생 시 발 미끄러짐·기준점 튐 없음
- [ ] 플레이트 위 아바타 합성 샷: 톤 위화감 없음(라이팅 방향·그림자 농도)
- [ ] 뷰포트 초기 로딩 < 3초 (플레이트 + 등장 캐릭터 프리로드)
- [ ] y기반 z-정렬 확인: 가구 폴리곤 뒤/앞 이동 시 전후 관계 자연스러움

## 5. 지오메트리 캘리브레이션 (플레이트 확정 후 1회)

새 플레이트의 공간 배치에 맞춰 아래를 **동기 갱신**한다 (좌표는 정규 0~1):

| 대상 | 파일 | 항목 |
|---|---|---|
| 프론트 좌표 정본 | `frontend/lib/office2d.ts` | `WALK_AREA`(보행 폴리곤) · `ROOMS`(방 폴리곤·라벨) · `OBSTACLES`(가구 충돌) · `SPAWNS`(스폰 4종) |
| 이동서버 검증 | `realtime/src/integration/FloorLayoutProvider.ts` (HORIZON) | 동일 폴리곤 미터 환산본 — **양쪽 불일치 = 유령 충돌/벽 통과** |
| 검증 | `realtime` scene-floor 테스트 + `npm run load-sim` | 폴리곤 정합·부하 재확인 |

> 화면비 1672:941을 유지하면 미터 스케일(20×11.256m)은 그대로 — 폴리곤 좌표만 새 배치에 맞춰 갱신.

## 6. 제작 경로 후보 (참고)

- 자체 제작(권장 — 톤 통제 최상): 아이소 플레이트 1장 + 캐릭터 시트. 스타일 가이드를 먼저 1장 확정 후 확장
- 외주/에셋 커미션: 본 문서를 워크오더로 그대로 전달 가능
- AI 생성 보조: 플레이트 초안 생성 → 수작업 클린업 (프레임 애니는 수작업 권장 — 프레임 간 일관성)
