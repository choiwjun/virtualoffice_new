## 1. 표면 요청 → 재정의된 문제 정의

### 사용자 초기 요청
"3D 가상오피스로 원격 협업을 하면서 회의·업무를 기록하고, 그걸 분기 인사평가에 반영하는 시스템을 만들고 싶어요."

### 재정의된 한 줄 정의
**기존 DailyLog ERP 위에 얹는 3D 프레즌스 + 협업 계층**

즉, 우리는:
- HR/근태/리포트/역량평가 시스템을 재구축하지 않는다
- 기존 사내 ERP(Space-Daily)를 Source of Truth로 유지한다 (조직·직원·근태·휴가·일일리포트)
- 3D 가상오피스(아바타·좌석·회의실) + 실시간 프레즌스 + LiveKit 화상회의 + 회의록/협업 기록을 위에 추가한다
- 그 협업 산출물(회의록·액션아이템·업무결과)을 배치(daily_reports 18:00) 및 관리자 확정 KPI push로 ERP에 전달해서, ERP가 분기별 인사평가 자료로 활용하게 한다 (회의 시간 등 시간 신호는 반감시·이중반영 방지로 KPI 미반영, D14)

## 2. 제품 정의 & 핵심 원칙

### 핵심 통찰: "예쁜 3D"가 아니라 "운영 허브"

오피스 경험은 미학이 아니라 **업무·회의·KPI가 자연스럽게 쌓이는 구조**가 핵심이다.

```
조직도(ERP) 
  ↓ [읽기 동기화]
우리 org_group (상위 그룹: 본부/부서) + 팀(ERP teams)
  ↓ [직원배정]
좌석 배치 (seat 배정, office_layout JSON 구동)
  ↓ [2.5D 시각화]
2.5D 클린플레이트 뷰포트 (플레이트 PNG 배경 + DOM 스프라이트 아바타 · 좌석 · 회의실 · 상태, D29)
  ↓ [아바타 출근/상태 변화]
실시간 Presence (Colyseus 권위 서버, 20Hz)
  ↓ [회의/협업]
회의 시작 → LiveKit 화상 → 회의록 + 액션아이템 생성
  ↓ [업무 기록]
work_log (결과물·완료도) + daily_status
  ↓ [KPI 산출]
협업 산출물 기반 KPI_result (AI 초안 → 관리자 검토 → 조정)
  ↓ [EOD Push]
ERP daily_reports + (신규) kpi_results 테이블로 전송
  ↓ [기말 평가]
ERP가 분기별 인사평가 자료 수집
```

### 장점(우리만 할 수 있는 것)
1. **ERP 완전 통합**: 직원·조직·근태·휴가는 항상 fresh (read-only DB 직접 접근)
2. **공간 기반 협업 추적**: 근접·회의실 점유·화상 참여를 자동으로 기록
3. **결과물 중심 평가**: 접속시간이 아니라 회의록·액션·완료도로 평가 (반감시 제거)
4. **운영 가시성**: 관리자가 3D맵에서 실시간으로 팀 상태·회의 현황 파악
5. **사무실 구조 코드화**: office_layout JSON으로 구동하므로 좌석·구역·회의실을 앱 빌드 없이 배포/롤백 가능
6. **단일 웹앱 경험**: 콘솔과 3D 뷰포트가 하나의 Next.js 앱 안에 통합 — 별도 데스크톱/별도앱 설치·이중 로그인 없음

## 6. KPI & 평가 원칙

### 핵심: 결과물 중심 평가 (과정 반감시 제거)

**반영되지 않는 신호** (반감시 방지):
- 접속 시간 (몇 시간 했는가)
- 채팅/메시지 빈도 (얼마나 말했는가)
- 근접 상호작용 빈도 (몇 번 만났는가)
- 화상요청 수신/거절 (얼마나 응했는가)

**반영되는 협업 신호** (결과물 중심):
1. **업무 결과물** (work_log)
   - 완료도: started/completed
   - 품질: result_url, issues 기록
   - 충실도: goal·category·next_action 작성 정도

2. **회의 기여도** (meeting_minute + action_item)
   - 회의 참여 횟수 × 회의록 충실도
   - 자신이 담당한 액션아이템 이행률
   - 회의에서 나온 결정사항 영향도

3. **업무 기록 충실도** (daily_reports)
   - today_work·tomorrow_plan 작성 완성도
   - blockers 해결을 위한 주도성

4. **보조**: 근태·출퇴근 (기초 근무조건) — **KPI 점수에는 직접 반영하지 않음**(ERP가 attendance 별도 반영, 이중 반영 금지, D14)
   - 출석률, 휴가 사용 패턴은 ERP 소관 (참고 지표)
   - `external`(외근/출장)은 수동 전환. **GPS 수집 기능 삭제**(데스크톱에 GPS 없음, D13/D20)

### AI 평가 프로세스
1. **정량 점수 = 결정론적 코드로 계산** (D14)
   - 완료 work_log 건수·충실도, 액션아이템 완료·기한준수 이행률, 회의록 작성 기여 등을 코드가 산출
   - 시간 비례 점수·회의 참석 기본점·생성 가점·근태 보정은 제거(반감시·이중반영 방지)
2. **AI 초안은 서술만** (Claude — 확정 기본)
   - AI는 강점/개선/근거를 **서술**하며 정량 점수를 산출하지 않음
   - 외부 AI 전송 시 실명→사번 가명화(D20)
3. **관리자 검토 & 조정**
   - AI 서술은 근거 자료, 최종 판단은 관리자. 정성적 맥락(팀 상황, 조직 변화, 개인 발전) 반영
4. **직원 이의신청 (상태머신, D15)**
   - 평가 공개 → 이의접수(7일) → 재검토 → 확정 → ERP push(final_score)
   - 기록 기반 재검토 가능

### Assumptions
1. 첫 배포는 사내 단일 조직(company_id 고정)이므로, 멀티테넌트 설계는 불필요.
2. ERP (Space-Daily) DB는 read-only 직접 접근 가능하고, 쓰기는 API 또는 신설 테이블.
3. 클라이언트는 단일 Next.js 웹앱 내 R3F 뷰포트로 제공 — 별도 데스크톱/별도앱 설치 불필요(D27). 포토리얼 품질은 Blender 오프라인 렌더를 굽고 깊이합성으로 재현하므로 실시간 GI 불필요.
4. 3D 사무실 구조는 office_layout JSON으로 동적 로드되므로, 매번 클라이언트 빌드할 필요 없음.
5. 정량 KPI 점수는 결정론적 코드가 산출하고, AI는 서술(강점/개선/근거)만 생성하며, 관리자가 항상 최종 검토(D14).
6. 직원의 도메인 이메일과 ERP users.id 매핑은 동기화 시 자동 수립.

### Validation criteria
- [ ] 페르소나 3종의 JTBD가 모두 구현된 기능으로 충족되는가?
- [ ] KPI 반영 신호들(work_log, meeting_minute, action_item)이 모두 수집 가능한가?
- [ ] 관리자 확정 KPI(final_score) → ERP kpi_results → 분기평가 전체 루프가 폐쇄되는가? (D15/D17)
- [ ] R3F 클라이언트 품질(깊이합성 픽셀정확 가림, 로딩<5초, Colyseus 동기화 p95<500ms)이 기준을 만족하는가? (D27)

### Risks
1. **ERP 브랜치 전환 지연**: ERP kpi_results 테이블 추가가 지연되면, 우리의 KPI push 쓰기가 블로킹됨 → **완화**: 초기 kpi_results를 우리 DB에만 쌓고(feature flag OFF), ERP 준비 후 backfill (D17)
2. **이동서버 성능 (설계 100명)**: Colyseus 권위 서버 동기화 성능 미검증 → **완화**: P3 이동서버 구현 후 + P7 부하 테스트, tick 20Hz, 100명 초과 시 AOI 필터링 (D22/D27)
3. **AI 평가 정확도**: 서술 초안 품질이 예상 수준 미만 → **완화**: 정량은 결정론적 코드로 고정(D14), AI 서술은 사용자 피드백으로 프롬프트 반복 개선
4. **사용자 피드백 곡선**: 사내 도그푸딩 중 UX 이슈 발견 시 개발 일정 슬립 → **완화**: Phase 4부터 **주 1회 이상 피드백 수집 체계**
5. **깊이합성 정합 (신규, D27)**: Blender 렌더 배경과 R3F 실시간 아바타의 깊이·조명 정합 실패 위험 → **완화**: P0 스파이크에서 오클루전 검증(**PASS 2026-07-08**), IBL 정합·Z깊이패스 기준 확립. 정합 붕괴 시 카메라 앵글/씬 단순화로 폴백
6. **STT 정확도 / 한국어 화자분리** (신규, D5/F): 회의록 자동 초안 품질·화자분리 정확도 미달 위험 → **완화**: P6 STT PoC, 누락률 <5% 미달 시 수동 회의록 + AI 요약으로 격하(기준 하향 재협의)
7. **개인정보 / 노동법 컴플라이언스** (신규, D20): 평가 목적 행동 데이터 수집 동의, 회의 녹음·STT 동의, 외부 LLM 전송 → **완화**: D20 컴플라이언스 원칙(고지·동의 절차, 사번 가명화, 보존기한, 최소수집 VIEW) 도입 전 이행
