### 1-1. 좌표계가 셋이었다 (D40)

증상은 하나였다 — 씬에서 회의실을 눌러도 아무 일이 없다. 파 보니 좌표계가 셋이었고, 셋 다 좌표를 "미터"라고 불렀다.

| 무엇 | 세계 |
|---|---|
| V3 씬 (화면에 그려지는 것) | 20 × 11.256m |
| 배포 레이아웃 (편집기 산출) | 자기 `dimensions` — 실측 23.8 × 18.5m |
| 이동서버 | 배포본을 그대로 시뮬레이션 |

- **클릭 무반응의 직접 원인**: 배포 방을 씬 상수로 정규화해 정규 y가 1.20~1.47이 됐고, `overflow-hidden`에 잘렸다. 방 카드를 여는 유일한 클릭 대상이 방 라벨인데 그게 화면 밖(y=1606px)에 있었다. **요소는 멀쩡했다** — 코드로 `.click()` 하니 카드가 정상으로 열렸고, 그래서 "위치 외엔 고장 없음"을 먼저 확정하고 고쳤다.
- **더 조용했던 것**: 서버는 배포 박스(23.8×18.5)를, 클라는 씬(20×11.256)을 돌리고 있었다. 씬이 배포 박스 **안에 들어가서** 이동 거부조차 나지 않았다 — 아무도 모르는 채 좌표만 틀어져 있었다.
- 해결은 D40: **화면에 그려진 씬이 사무실**이고 배포본은 도면. 코드베이스가 이미 세 곳(30e21bb·`applySeatCoords`·`V3_ROOMS` 라벨)에서 택한 방향인데 `activeRooms`만 남아 있었다.

### 1-2. 정본 없는 연결 두 건 (D40-d · D39 후속)

어제 D39가 "정본이 없으면 화면이 지어낸다"를 확립했는데, 같은 병이 두 군데 더 있었다.

- **씬 방 ↔ DB 회의실**: 이름 문자열 일치로 때우고 있었다. 씬 라벨이 영어라 **한국어로 이름 붙인 회사는 한 번도 맞지 않는다** — 그 회사 오피스에서는 모든 방이 "회의실 정보 없음"이다. `room.scene_key`로 정본을 세우고(0012), 연결 화면을 만들었다(씬 기준 — 관리자는 자기 회의실 목록보다 자기가 보는 사무실을 안다).
- **조직도 그래프**: D39로 이름은 맞췄지만 **구조는 여전히 둘**이었다(좌측 트리 3단 vs 그래프 2단). 그래프가 `org_group` 계층을 그대로 그리게 했다.

검증 방법이 결정적이었다 — DB 방 이름을 `Board Room` → `대회의실`로 바꿔도 카드가 살아 있다. 예전 코드였다면 여기서 죽는다.

## 3. 이번 세션에서 확립된 레시피

**"좌표를 미터라고 부르는 것끼리도 세계가 다를 수 있다"** — 두 좌표계를 잇기 전에 **원점과 크기가 같은지** 먼저 묻는다. 크기가 다르면 같은 (10, 5)가 다른 자리를 뜻한다. 더 나쁜 건 한쪽이 다른 쪽 **안에 들어갈 때**다 — 경계 검사가 통과해 버려서 아무 에러 없이 조용히 어긋난다. 그래서 경계 검사만으로는 부족하고 **크기 대조**가 필요하다(D40-c).

**"조용한 고장이 시끄러운 고장보다 비싸다"** — 오늘 고친 것 중 셋이 조용했다. ① 배포 도면이 화면 밖(초록 필은 "반영됨"이라 말하고 있었다) ② 서버·클라 세계 불일치(거부조차 안 났다) ③ nullability 드리프트(삽입은 통과). 조용한 실패를 만드는 코드에는 **반드시 큰 소리로 말하는 경로**를 같이 넣는다 — exit 1, 한 번은 반드시 남는 경고, 화면에 세어 보여 주기.

**UI 없는 정본은 반쪽** — D39(팀)에서 조직도 수정 경로를 냈듯, D40-d(회의실)도 연결 화면을 같이 냈다. 컬럼과 API만 만들고 끝내면 관리자는 손댈 수 없고, 그 정본은 시딩 스크립트 전용이 된다.

## 5. 함정 / 주의

- **⚠ `next build`와 `next dev`가 같은 `.next`를 쓴다.** dev 서버가 떠 있는데 build를 돌리면 dev가 정적 청크 404를 뱉으며 "로딩 중…"에서 멈춘다(오늘 실제로 당했다). 복구 = dev 종료 → `rm -rf .next` → 재기동.
- **⚠ 같은 테스트 스위트를 동시에 두 번 돌리지 말 것.** 백그라운드로 돌려 놓고 포그라운드로 또 띄웠더니 CPU를 나눠 쓰며 3분짜리가 11분 44초가 됐고 포그라운드가 타임아웃에 잘렸다.
- **~~Windows에서 `next build`·`vitest` 실행 불가~~ → 사실이 아니다.** 오늘 둘 다 통과했다(`vitest` 56 passed, `next build` exit 0). 전날 핸드오프의 이 항목은 틀렸다. 단, **`backend/.venv`는 WSL용이 맞다** — Windows에서는 `python -m venv` + `pip install -r requirements.txt`로 새로 만들어야 한다(`asyncpg` 제외).
- **⚠ `PUBLIC_APP_URL`을 운영에서 반드시 설정** — E4 링크의 호스트는 백엔드가 아니라 **프론트** 주소다.
- **드리프트는 컬럼 이름만 보면 안 잡힌다** — 이제 `scripts/check_schema_drift.py`가 타입·nullability까지 본다. pull 직후 한 번 돌리는 습관이 어제 두 사고를 막았을 것이다.
- **PowerShell로 한글 소스를 rewrite 금지** — `Get-Content | Set-Content`가 CP949로 읽고 UTF-8로 써서 한글 주석을 깨뜨린다.
- **커밋 메시지 백틱 금지** — bash `-m "…`토큰`…"`은 명령치환. 파일(`-F`)로 넘긴다.
